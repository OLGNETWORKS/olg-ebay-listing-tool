## Objetivo

Construir el shell interno del editor con una biblioteca visual para los bloques existentes de `DescriptionDocument` y un preview responsive alimentado únicamente por fixtures locales. El editor conserva JSON por bloques como fuente editable y usa el compilador integrado para producir la vista previa; no persiste HTML ni conecta todavía el flujo vertical.

## Dependencias y contratos congelados

- T2 está integrada y verificada; consume `ListingProfile`, `DescriptionDocument`, sus tipos de bloque y `Compiler` desde `src/lib/contracts/**` sin modificarlos.
- `DescriptionDocument` conserva `schemaVersion`, `theme` y `blocks[]`; el JSON es la única fuente editable.
- `compileDescription(document)` devuelve HTML/CSS estático, warnings y errors. La interfaz presenta esos resultados sin duplicar ni modificar el compilador.
- T3 está integrada, pero T4 permanece independiente de Prisma y del repositorio de perfiles: usa un `ListingProfile` fixture local. T6 realizará el ensamble con persistencia y gateway.
- No se añaden dependencias ni se cambian scripts compartidos; el corte usa React, Next.js y Vitest ya instalados.

## Criterios verificables del corte

- El shell distingue con claridad datos del producto, biblioteca/estructura de bloques y preview.
- La biblioteca representa los cinco tipos existentes: heading, paragraph, bullet-list, image y specifications.
- Editar el fixture actualiza el `DescriptionDocument` y recompila el preview sin convertir el HTML generado en estado editable.
- Warnings y errors del compilador son visibles y un resultado inválido no se presenta como preview válido.
- El layout funciona en viewport de escritorio y móvil, con navegación y controles accesibles por teclado y etiquetas explícitas.
- No existe botón, ruta ni efecto que publique, revise, termine o valide anuncios en eBay.
