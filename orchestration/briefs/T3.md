## Objetivo

Persistir perfiles internos de producto independientes de anuncios activos mediante PostgreSQL como objetivo y Prisma como adaptador. El corte debe guardar `ListingProfile`, conservar cada revisión como snapshot, detectar conflictos de revisión y permitir buscar por ID o SKU sin realizar tráfico a eBay.

## Dependencias y contratos congelados

- T2 está integrada y verificada; se consumen `ListingProfile` y `DescriptionDocument` desde `src/lib/contracts/**` sin modificarlos.
- El JSON de `descriptionDocument` sigue siendo la fuente editable; el HTML compilado no se guarda como fuente primaria.
- Un perfil nuevo comienza en revisión 1. Una actualización válida incrementa exactamente una revisión.
- Cada guardado crea un snapshot inmutable y único por `(profileId, revision)`.
- `profileId` y `sku` son identidades estables; los conflictos concurrentes fallan de forma explícita.
- PostgreSQL es el único provider del schema. Las pruebas no requieren una base real ni credenciales.
